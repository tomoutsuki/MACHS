Understanding FABEO Attribute-Based Encryption

FABEO (Fast Attribute-based Encryption with Optimal Security) allows fine-grained access control where:

  • CP-ABE (Ciphertext-Policy): Data is encrypted with a policy, users need matching attributes
  • KP-ABE (Key-Policy): User keys contain policies, data is encrypted with attributes
  • Policies: Boolean expressions defining who can access the data
  • Attributes: Key-value pairs that describe user roles, departments, clearances, etc.

Demo Scenario: Hospital Data Access

✅ Scenario 1: Cardiologist Access (SUCCESS)

Situation: A cardiologist needs to access heart patient data

Step 1: Encrypt Patient Data

Data: "Patient John Doe has severe coronary artery disease requiring immediate intervention" Policy: "(role:doctor AND department:cardiology)" Scheme: CP-ABE

Step 2: Doctor Attempts Access

User Attributes: "role:doctor,department:cardiology,clearance:high" Result: ✅ DECRYPTION SUCCESSFUL - User has required attributes

❌ Scenario 2: Unauthorized Access (FAILURE)

Situation: A nurse from emergency department tries to access cardiology patient data

Step 1: Same Encrypted Data

Data: "Patient John Doe has severe coronary artery disease requiring immediate intervention" Policy: "(role:doctor AND department:cardiology)" Scheme: CP-ABE

Step 2: Nurse Attempts Access

User Attributes: "role:nurse,department:emergency,clearance:medium" Result: ❌ DECRYPTION FAILED - User lacks required attributes (not a doctor in cardiology)

✅ Scenario 3: Emergency Override (SUCCESS)

Situation: Emergency access with admin privileges

Step 1: Encrypt with Emergency Policy

Data: "Critical patient vitals and emergency contact information" Policy: "(role:doctor AND department:emergency) OR role:admin" Scheme: CP-ABE

Step 2: Admin Attempts Access

User Attributes: "role:admin,clearance:highest" Result: ✅ DECRYPTION SUCCESSFUL - Admin role satisfies the OR condition

Testing Steps in the Frontend

1. Create a Test Patient

  1. Go to "Patient Management" tab
  2. Fill in patient details:
    Name: John Doe Age: 45 Gender: Male Diagnosis: Severe coronary artery disease Policy: (role:doctor AND department:cardiology)
  3. Click "Create Patient" - data will be automatically encrypted

2. Test Manual Encryption

  1. Go to "Encryption Testing" tab
  2. Enter test data:
    Data: "Confidential medical research data" Policy: "(role:researcher AND clearance:high) OR role:admin" Scheme: CP-ABE
  3. Click "Encrypt Data" and copy the encrypted result

3. Test Authorized Decryption

  1. Go to "Decryption Testing" tab
  2. Paste the encrypted data
  3. Enter matching attributes:
    User Attributes: "role:researcher,clearance:high,department:research"
  4. Click "Decrypt Data" - should succeed ✅

4. Test Unauthorized Decryption

  1. Use the same encrypted data
  2. Enter non-matching attributes:
    User Attributes: "role:nurse,clearance:low,department:general"
  3. Click "Decrypt Data" - should fail ❌
